# ReBackup — Languages (German / English)

Date: 2026-10-02
Status: Approved (user, in chat)

## 1. Decisions

| Topic | Decision |
|---|---|
| Languages | English (`en-US`) and German (`de-DE`). |
| Label files | One JSON file per language, `src/ReBackup.App/Locales/en-US.json` and `de-DE.json`, embedded in the exe. Hierarchical objects; a label is addressed by its dotted path, e.g. `ui.ignore.title` ↔ `{"ui":{"ignore":{"title":"…"}}}`. Leaves are strings. |
| Placeholders | Named: `"Backup of \"{plan}\" completed in {duration}."`; `{{` / `}}` escape braces. Numbers and dates are formatted by the caller with the current culture before they are passed in (or via a format suffix `{count:N0}` if the plan chooses to support it). |
| Fallback | Missing in the chosen language → English → the key itself (so a gap is visible, never a crash). |
| Parity | A Core-free test (App-side helper usable from a test project, or a test that parses both JSON files) asserts both files have exactly the same key set and the same placeholders per key. |
| Switching | Instant, without restart, like the theme: XAML texts bind to the localization service (markup extension with a binding to an indexer that raises change notifications); view models re-raise their text properties on `LanguageChanged`. `CultureInfo.CurrentCulture`/`CurrentUICulture` and WPF `Language` follow the chosen language, so dates and numbers format accordingly (de: `18.690`, `Fr 02.10.`). |
| Selection | A flag button in the left rail above the theme button opens a dropdown with 🇩🇪 Deutsch and 🇬🇧 English (flags drawn as vector images in Theme, not emoji). Stored in `settings.json` as `language` (`"de-DE"` / `"en-US"`). First start: German when the Windows UI language is German, otherwise English. Unknown values load as that default. Settings window offers the same choice. |
| Scope | Every text the App shows: tabs, cards, buttons, tooltips, automation names, dialogs and message boxes the app raises, status/footer messages, tray menu and balloon notifications, empty states, the restore and conflict dialogs. |
| Core messages | Validation messages that Core produces for live UI (plan validation, trigger validation, retention rule errors, anchor hints, schedule notes, catalog ownership reasons) become keys + arguments (e.g. a `Message(string Key, IReadOnlyDictionary<string,object?> Args)` record or equivalent) so the App renders them in the chosen language; their English text moves into en-US.json. |
| Stored texts stay English | Texts persisted to disk (run log `reason`, `warnings`, skipped reasons, manifests) remain English; the History tab translates known reasons by mapping them to keys where a stable mapping exists, otherwise shows them as stored. |

## 2. Testing

- Core: validators return keys + args (existing tests adapted to assert keys; English rendering tested once).
- Locales: parity test (same keys, same placeholders), fallback test, placeholder formatting test, default-language selection (German Windows → de-DE).
- App: build 0 warnings; controller's offscreen screenshots of every tab in German and English, Dark and Light; manual switch test.
