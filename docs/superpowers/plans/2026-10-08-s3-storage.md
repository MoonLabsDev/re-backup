# S3 Storage Provider Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Amazon S3 `IStorage` with encrypted per-app connections, a connection tester and a shared connection dialog.

**Architecture:** New library `ReBackup.Storage.S3` (AWSSDK.S3 + DPAPI) implementing the existing `IStorage` contract, a decorating `S3StorageFactory` for kind `"s3"`, and a WPF dialog in `ReBackup.Shared.Wpf`. Integration tests reuse the abstract `StorageContractTests` against MinIO in Docker.

**Tech Stack:** C# / .NET 9, AWSSDK.S3, System.Security.Cryptography.ProtectedData, WPF + CommunityToolkit.Mvvm, xUnit 2.9 + FluentAssertions 7, Testcontainers.Minio, Xunit.SkippableFact.

**Spec:** `docs/superpowers/specs/2026-10-08-s3-storage-design.md`

## Global Constraints

- Branch `feature/s3-storage`. After every task: `dotnet build ReBackup.sln` has no errors and no warnings; `dotnet test ReBackup.sln` is green (MinIO tests may be reported *skipped* only when Docker is unavailable).
- `ReBackup.Storage` stays BCL-only. `ReBackup.Storage.S3` → `ReBackup.Storage`, `ReBackup.Shared`; packages only `AWSSDK.S3`, `System.Security.Cryptography.ProtectedData`. `ReBackup.Shared.Wpf` → `ReBackup.Shared`, `ReBackup.Storage.S3`. Nothing references `ReBackup.Core` / `ReBackup.App`.
- AWS S3 only; credentials = access key ID + secret; the plain secret is never logged, never in exception messages, never written unencrypted.
- DPAPI: `DataProtectionScope.CurrentUser`, entropy = UTF-8 bytes of `"ReBackup.S3.v1"`.
- `connections.json` format: `{ "formatVersion": 1, "connections": [ { "id", "name", "region", "bucket", "accessKeyId", "secretProtected" } ] }`, written with `AtomicFile` + `JsonDefaults`.
- Capabilities of `S3Storage`: `CaseSensitive` only. Keys ≤ 1024 UTF-8 bytes. Keys ending in `/` are directories.
- Writer: in-memory buffer up to 16 MiB → `PutObject`; beyond → multipart, 16 MiB parts, part size doubles after every 1000 parts; exclusive commit uses `If-None-Match: *`; 412 → `StorageConflictException`; dispose without commit aborts (never throws).
- `DeleteObjects` batches of 1000.
- Package versions: pin the latest stable at implementation time and record them in the task report.
- Commit style: conventional; end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Code style: match the existing projects (file-scoped namespaces, nullable, XML docs in the same density and tone).

## Review Focus

1. **Undecryptable secret after moving to another PC/account** — the connection must load with `Secret = null`, stay in the file, and opening a storage must say "re-enter secret", never crash or silently drop the entry → tests in Task 1 and Task 5.
2. **Network drop mid-upload or mid-listing** — must surface as `StorageUnavailableException`, and an interrupted multipart upload must be aborted, not left billing → tests in Task 3 (fake client) and Task 2 (mapping).
3. **Concurrent exclusive create of the same key** (two runs racing for `re-pending.json`) — exactly one wins, the other gets `StorageConflictException` → test in Task 4 (MinIO).
4. **Prefix edge cases** — `""` (whole bucket), nested prefix, keys with spaces/umlauts/`+`, a console "folder" placeholder `x/` — listing returns correct relative paths and never shows the placeholder as a file → tests in Tasks 2 and 4.
5. **Wrong region configured** — the tester reports the bucket's real region and the dialog can apply it, instead of a generic failure → tests in Tasks 5 and 6.
