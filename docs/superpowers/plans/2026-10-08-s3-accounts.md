# S3 Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Credentials move into S3 accounts; connections (bucket + region) refer to an account — in the shared S3 layer of re-backup, adopted by re-s3.

**Architecture:** Stored types `S3Account` and `S3ConnectionInfo` in `connections.json` v2 with automatic v1 migration; the existing resolved `S3Connection` stays and is produced by `S3ConnectionResolver`, so S3Storage, the writer and the tester stay untouched. New account dialogs in Shared.Wpf; the connection dialog picks an account. re-s3 bumps the submodule and adopts.

**Tech Stack:** C# / .NET 9, WPF + CommunityToolkit.Mvvm, AWSSDK.S3, xUnit 2.9 + FluentAssertions 7, LocalStack (Testcontainers) for the account test.

**Spec:** `docs/superpowers/specs/2026-10-08-s3-accounts-design.md` (re-backup)

## Review Focus

1. **v1 file with two connections sharing a key but different (or one undecryptable) blobs** — migration must keep the first entry's blob, never invent a secret, never lose a connection → Task 1 test `Migration_with_same_key_keeps_first_blob_and_all_connections`.
2. **Account secret rotated while a connection's storage is cached** — the factory must use the new secret (cache key includes the secret) → Task 1 test `Changed_account_secret_gives_a_new_client`.
3. **Deleting an account still in use** — refused with the connection names, file unchanged → Task 1 store test + Task 2 VM test.
4. **Connection dialog editing a connection whose account was deleted elsewhere** — must show "account required", not crash → Task 2 test `Missing_account_requires_choosing_one`.
5. **re-s3 started on a v1 `connections.json`** — connections keep working without the user doing anything → Task 3 test `V1_connections_still_open_storages`.

```csharp
public sealed record S3Account(string Id, string Name, string AccessKeyId, string? Secret)
{ public bool NeedsSecret => Secret is null; public override string ToString(); }          // no secret
public sealed record S3ConnectionInfo(string Id, string Name, string Region, string Bucket, string AccountId);
public static class S3ConnectionResolver { public static S3Connection? Resolve(S3ConnectionInfo c, S3Account? a); }
// Resolve: a null → null; else new S3Connection(c.Id, c.Name, c.Region, c.Bucket, a.AccessKeyId, a.Secret)
public sealed class S3ConnectionStore
{
    public S3ConnectionStore(string filePath);
    public IReadOnlyList<S3Account> LoadAccounts();
    public S3Account? TryGetAccount(string id);
    public void SaveAccount(S3Account account);           // insert/replace by id; Secret null keeps stored blob (new account with null secret → ArgumentException)
    public void DeleteAccount(string id);                 // in use → InvalidOperationException (message lists connection names)
    public IReadOnlyList<S3ConnectionInfo> LoadAll();
    public S3ConnectionInfo? TryGet(string id);
    public void Save(S3ConnectionInfo connection);        // unknown AccountId → ArgumentException
    public void Delete(string id);
    public S3Connection? TryResolve(string connectionId);
    public IReadOnlyList<S3ConnectionInfo> ConnectionsUsing(string accountId);
}
// S3ConnectionTester gains:
public Task<S3CheckResult> RunAccountAsync(S3Account account, CancellationToken ct);   // result Check = S3Check.Account
public enum S3Check { Account, Bucket, Versioning, List, WriteDelete, Lifecycle }        // Account added first
// S3MessageKeys: AccountNoList = "s3.check.accountNoList"
```
Removed: `S3ConnectionStore.Save(S3Connection)` / `LoadAll()` returning `S3Connection` (callers move to the new members; re-backup itself has no app caller).
